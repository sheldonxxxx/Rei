# Trigger reports in the home chat

A prompt/skill trigger runs in its own chat session. Its report is a background input to the agent's home conversation, where the assistant processes it with the existing conversation and writes a normal reply. The raw report is hidden in both modes; Full mode shows only a compact background-result label and a link to open the source session. Existing historical trigger messages without an associated home run keep their original display.

`always` uses the explicitly saved report, or the complete final answer as fallback. `on_change` delivers only when the trigger agent calls `report()`. `never` suppresses result delivery. Reports support up to 64,000 characters, preserving paragraphs and Markdown. Trigger failure and automatic-pause results also go through the home assistant. Plain `notify` reminders keep their direct, model-free delivery.

The trigger runner writes a structured `home_note` outbox row in its completion transaction. The adapter accepts it as an idempotent home run, with a `rei.input` entry of role `trigger` and model-only instructions describing it as background information rather than a new user instruction. It uses the same home conversation and normal run queue. Source-session provenance labels propagate to the home session. The reaction is unattended (`direct` false in the command ledger) and carries no `triggerRunId`, preventing it from being treated as another execution of the original trigger.

Acceptance and replay use the same request ID. A crash after acceptance but before marking the outbox delivered reuses the accepted run, rather than creating another response. Notification events are queued only after the home reply completes, using its text (subject to the existing notification preview limit). Raw reports are not used as sidebar previews or live announcements. A silent check with no report starts no home turn or notification. Context-only memory-suggestion notes append to the home conversation without starting a turn.

The home assistant can call `dismiss_event` to keep an event silent. The tool only accepts a running home turn whose input is a worker report or trigger result; it cannot dismiss a direct user request. The choice is durable on the run. Background replies are held internal while processing, and dismissed replies remain internal after completion; their text is not streamed, indexed as a reply, used as a sidebar preview, or sent in a notification. Full mode keeps a compact source-session link. Worker and trigger completion previews use the first 1,000 characters of the result, not a generated summary. The complete saved trigger report still supports its separate 64,000-character limit; the main assistant can open the source session for details.
